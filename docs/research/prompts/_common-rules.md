# Common rules for every nyms research prompt

Context: `nyms` is a new, public, MIT Python package (repo thorwhalen/nyms) for reversible pseudonymisation of text before it is sent to an AI service: a deterministic (non-AI) detection pass over text for personal and sensitive identifiers, replacement by surrogates (pseudonyms) generated by a configurable strategy, a reversible mapping store with managed keys, re-identification of AI output, and an optional model-based second detection pass. Primary languages of the text: Danish and English (EU, GDPR). Primary users: coding agents and the developer who embeds it; the end beneficiary is a private individual preparing documents (legal, financial, medical) for an AI assistant.

In-house material already found (do not repeat it, build on it): the `openloops.egress` module (regex credential patterns, path rewriting, raise-on-secret policy); the `dol` package (key-value store facade, `MutableMapping`); the `cw` package (CLI from functions); the `hm` package (mnemonic Major System: digits to phonemes); `config2py` (secrets and configuration resolution); `aix` (AI provider facade); `creel` (LLM-driven typed extraction). No PII detection, pseudonymisation or format-preserving encryption exists in-house.

Rules: every claim has a source; number references in order of first citation as [1], [2] with a REFERENCES section of `[name](url)` links (Vancouver style); say when something cannot be verified; label estimates as estimates; use expert terminology (pseudonymisation, tokenisation, surrogate generation, keyed hashing, format-preserving encryption, re-identification risk, key management, named-entity recognition) and define each on first use; lowercase kebab-case filename; never hard-wrap prose (one line per paragraph or list item); this is a public repo: no private names, client names, people or quotes from private material; invented examples only. Use comparison tables with a verdict column where options are compared. About two to four pages. Format: title line, an italic line with date, scope and what it serves, then "## Summary and recommendation" (five to ten lines), then the body sections, then "## Open questions", then "## REFERENCES".

Reply with at most two lines: the main finding and the path.
