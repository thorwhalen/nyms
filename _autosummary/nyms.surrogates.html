nyms.surrogates#

Surrogate (pseudonym) generation: what replaces a detected value.

A surrogate strategy is a callable (entity_type, value, *, vault) -> str that returns the replacement for a value seen for the first time; the mapping store calls it once per new value and remembers the answer, so every later occurrence gets the same surrogate. vault is the store itself, exposing __contains__ (is this surrogate taken?) and count(entity_type), which is all a strategy needs to avoid collisions or number things.

Four strategies, matching the surrogate research (docs/research/surrogates-crypto-and-keys.md):

  • Counter: [PERSON_1], [CPR_2]. The default. Bracketed typed tokens were the form LLMs altered least in the one benchmark found, and the counter is per project (persisted with the store), so the same person is [PERSON_1] in every document.

  • KeyedWords: HMAC-SHA-256 of the value under a secret key, rendered as readable words from a word list ([PERSON:alder-brook], or name-shaped Alder Brook). The same key gives the same surrogate on any machine without sharing a store, which is the property the vault lacks. Never unkeyed: a plain hash of a CPR number falls to enumeration.

  • RandomWords: readable words from random bytes. A classic tokenisation vault.

  • Aliases: the user’s own choice for some values (“call the landlord Mr Green”), with any other strategy as the fallback.

The rendering of bytes to words (words_from_bytes()) is separate from where the bytes come from, and is the tool the user asked for (“a cryptographic hash mapped to a sequence of letters that is actually readable”). It also stands alone:

>>> words_from_bytes(b'\x00' * 8, n=2)
['aardvark', 'aardvark']
>>> Counter()('PERSON', 'Hans Jensen', vault=_EmptyVault())
'[PERSON_1]'
>>> KeyedWords(b'k' * 32)('CPR', '010190-1234', vault=_EmptyVault())
'[CPR:...]'

nyms.surrogates.keyed_digest(key, entity_type, value)[source]#

HMAC-SHA-256 of entity_type || NUL || value under key.

The type is part of the message so a person and a company with the same string get different surrogates. The key must be secret: with a public key this is an unkeyed hash and a low-entropy identifier (a CPR number, a phone number) is recovered by enumeration.

Return type:

bytes

nyms.surrogates.syllables_from_bytes(data, *, n=3)[source]#

Render data as a pronounceable made-up word of n consonant-vowel syllables.

Needs no word list and never collides with a dictionary word, at the cost of looking invented. 70 syllables, about 6.1 bits each.

>>> syllables_from_bytes(b'\x00\x00\x00', n=3)
'bababa'
Return type:

str

nyms.surrogates.words_from_bytes(data, *, n=2, wordlist=None)[source]#

Render data as n words from wordlist (default: the EFF short list).

The integer value of the bytes is written in base len(wordlist); the lowest n digits become words. Each word of the default list carries log2(1296) = 10.3 bits, so two words identify about 1.7 million values and three about 2.2 billion.

>>> words_from_bytes(bytes([0, 0, 0, 1]), n=2)
['aardvark', 'abandoned']
Return type:

list[str]
